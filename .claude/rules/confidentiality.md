# 회사를 짐작할 수 있는 내용은 쓰지 않는다

이 저장소는 공개되어 있고 글은 공개 블로그에 실린다. 회사 일에서 얻은 경험으로 쓰는 글이라도, 읽는 사람이 어느 회사인지, 또는 회사의 규모·사업·조직이 어떤지 짐작할 수 있는 내용은 <strong>절대 쓰지 않는다</strong>. 글 본문뿐 아니라 frontmatter, 이미지, 코드 블록, HTML 주석, 커밋 메시지, PR 제목과 본문까지 모두 해당한다.

이 규칙 파일에도 실제 회사 이름이나 식별자를 예로 들지 않는다. 예를 들면 그것이 곧 노출이다.

## 쓰지 않는 것

| 종류 | 쓰지 않는 것 | 대신 쓰는 것 |
| --- | --- | --- |
| 이름 | 회사·서비스·제품·팀·사람 이름, 동료의 계정 | 쓰지 않는다. 필요하면 "한 서비스", "운영 중인 앱" |
| 식별자 | 도메인, 클라우드 계정 ID, ARN, 클러스터·노드 그룹·네임스페이스·레포·버킷·큐 이름, IP 대역, 사내 주소 | `my-cluster`, `example.com`, `<account-id>`처럼 자리표시 값 |
| 규모 | 노드·노드 그룹·인스턴스 대수, 서비스·앱·크론·레포 개수, 거꾸로 대수를 계산할 수 있는 절대값(요청값 합계, 코어 합계 등) | 비율("셋 중 하나"), 배수("실사용의 60배"), "여러", "작은 전용 그룹" |
| 사업과 고객 | 사업 영역, 다루는 고객 데이터의 종류, 고객 수와 매출 | 설명에 꼭 필요하면 직접 만든 가상의 예. 가상이라고 밝힌다 |
| 조직 | 팀 구성, 다른 팀의 설정과 결정, 사내 절차와 담당자 | "다른 운영 사례에서는", "흔히" |
| 사내 도구 | 사내에서만 쓰는 도구, 흔치 않은 도구 조합, 자체 호스팅 서비스 이름 | 일반 이름("사내 Git 서버", "이슈 트래커") |
| 일시 | 장애·배포의 날짜와 시각 | "어느 날", "배포 직후". 걸린 시간(50분, 1시간)은 써도 된다 |
| 이미지 | 콘솔·대시보드 캡처에 보이는 계정 ID, 리소스 이름, 사내 주소 | 가리거나 다시 그린다 |

## 그대로 써도 되는 것

- 공식 문서에 나오는 일반 사실과 기본값.
- 비율, 걸린 시간, 배수처럼 규모를 되짚을 수 없는 측정값.
- 인스턴스 종류나 Kubernetes 버전처럼 흔한 선택. 대수와 함께 쓰지 않는다.
- 직접 만든 가상의 값. 가상이라고 밝힌다.

## 판정

"이 문장 하나로, 또는 다른 글과 합쳐서 회사를 짚을 수 있나?" 짚을 수 있으면 쓰지 않는다. 한 글에서는 괜찮아도 다른 글의 숫자와 합치면 규모가 나오는 경우가 있다. 예를 들어 한 글에 노드 크기를, 다른 글에 예약 합계를 쓰면 노드 대수를 계산할 수 있다.

애매하면 쓰지 말고 글쓴이에게 묻는다.

## 이미 쓴 글이나 초안에서 발견하면

조용히 고치지 말고 어느 글의 어느 문장인지 글쓴이에게 알린다. 이미 공개된 글이면 git 이력과 검색 엔진에 남아 있으므로, 고치는 것만으로 충분한지도 함께 묻는다.
