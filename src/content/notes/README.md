# 노트 (제텔카스텐)

`ko/`에 넣은 노트는 `/ko/notes/<slug>/`로 발행되고, `/ko/notes/`는 `index.md`로 쓰는 색인이다. 파일을 넣는 것이 곧 발행이다.

## 노트 쓰는 법

- 노트 하나에는 하나의 주장만 담는다. 여러 주제가 섞이면 파일을 쪼개고 서로 링크한다.
- 파일명이 곧 제목이고 식별자다. 명사가 아니라 주장 문장으로 짓는다. 예: `학습은 기억이 아니라 이해다.md`
- frontmatter는 쓰지 않는다. 첫 문단이 검색 결과와 소셜 카드의 설명으로 쓰인다.
- 다른 노트는 `[[제목]]` 또는 `[[제목|본문에 보일 말]]`로 연결한다. 제목은 파일명과 글자 하나까지 같아야 한다.
- 아직 없는 노트를 가리켜도 된다. 링크가 아니라 일반 글자로 나오고, 그 파일을 만들면 저절로 링크가 된다.
- 연결받은 노트에는 "이 노트를 참조하는 노트" 목록이 빌드 때 자동으로 붙는다. 따로 적지 않는다.
- 폴더로 분류하지 않는다. 구조는 링크가 만든다.

## 경로

- `/ko/notes/`는 색인이다. 아래 "색인" 절을 따른다.
- 노트는 `/ko/notes/<slug>/`다. slug는 제목에서 글자와 숫자만 남기고 나머지를 `-`로 바꾼 것으로, 블로그 태그 페이지와 같은 규칙이다.
- 제목을 바꾸면 URL도 바뀌고, 그 노트를 가리키던 `[[제목]]`은 일반 글자가 된다. 다른 노트의 링크도 함께 고친다.

## 색인

`/ko/notes/`는 모든 노트를 늘어놓는 목차가 아니라 색인이다. 색인의 본문은 `src/content/notes/index.md`에 손으로 쓴다.

- 키워드를 가나다순으로 늘어놓고, 키워드마다 진입 노트 1~3개만 `[[제목]]`으로 건다. 형식은 `- 키워드 — [[노트 제목]] · [[노트 제목]]`이다.
- 모든 노트를 싣지 않는다. 대부분의 노트는 색인에 없고, 진입 노트에서 링크와 백링크를 따라가며 만난다.
- 한 키워드에 걸고 싶은 노트가 넷 이상이면 색인을 늘리지 않는다. 그 노트들의 링크를 모은 구조 노트를 하나 만들고 색인은 그 노트만 가리킨다.
- 키워드는 노트의 주제가 아니라 "나중에 어떤 질문을 들고 찾아올까"를 기준으로 고른다.
- 새 노트를 만들 때마다 색인에 넣을지 판단한다. 기존 노트에 링크를 거는 것으로 충분하면 색인은 건드리지 않는다.
- 색인의 위키링크도 노트와 같은 규칙을 따른다. 없는 노트를 가리키면 일반 글자로 남는다.

근거는 루만의 실제 색인이다. 노트 약 6만 7천 장에 키워드 3,200개였고, 키워드마다 1~4곳만 적었다. 나머지는 노트 사이의 참조로 찾는다는 전제였다. `system`처럼 그의 핵심 개념도 항목이 하나였다. 아렌스도 색인은 키워드당 진입 노트 한둘이며, 링크를 모아 둔 노트가 진입 노트로 알맞다고 정리한다.

- Johannes Schmidt, "Niklas Luhmann's Card Index: Thinking Tool, Communication Partner, Publication Machine"
- Sönke Ahrens, 『How to Take Smart Notes』, 색인과 키워드 절
- zettelkasten.de, "Introduction to the Zettelkasten Method", The Fixed Address of Each Note와 Structure Notes 절

## Obsidian

이 폴더 `src/content/notes`를 vault로 열면 위키링크 자동 완성과 그래프를 그대로 쓸 수 있다. 설정 폴더 `.obsidian`은 git에서 무시한다. Obsidian의 링크 자동 갱신을 켜 두면 제목을 바꿀 때 다른 노트의 링크도 함께 바뀐다.

## 확인

`npm run check`가 빌드하면서 노트 페이지의 내부 링크까지 검사한다. 미리보기는 `npm run preview` 뒤 `/ko/notes/`에서 본다.

노트를 전부 지워 `ko/`가 비면 Astro가 이전 빌드 캐시의 노트를 지우지 않고 그대로 다시 만든다. 그때만 `npx astro build --force`로 캐시를 한 번 비운다. 노트가 하나라도 남아 있으면 삭제와 제목 변경은 다음 빌드에 바로 반영된다.
